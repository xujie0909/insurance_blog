# 保险文章流水线

一篇文章从选题到上线的完整流程。每一步都有**完成标准**，达到了才进下一步。

动笔前必读，全程遵守：

- [writing/写作规范.md](../../../writing/写作规范.md)：读者、立场、七段骨架、语言、信息来源
- [writing/AI味规则.md](../../../writing/AI味规则.md)：作者维护的去 AI 味规则，优先级最高

流水线里的 `fact-checker`、`reader-reviewer`、`visual-reviewer` 定义在 `.claude/agents/`。某个 agent 类型不可用时，改派 `general-purpose`，并在任务开头要求它先读 `.claude/agents/<名字>.md`、完全按其中的说明执行。

## 0. 判断输入

| 输入 | 路径 |
|---|---|
| 概念或话题（“等待期”“有社保还要买保险吗”） | 知识文章，写到 `content/posts/<slug>.md` |
| 具体产品、条款 PDF | 产品解析：第 3 步和第 4 步改用 [insurance-product-page](../insurance-product-page/SKILL.md) 的提取、文章结构和 H5 规范，其余步骤照走 |
| 修改或重审已有文章 | 从第 5 步开始，把现有文章当初稿 |
| “写某个主题的一批”“写这一批” | 批量模式，见文末 |

所有文章都放在 `content/posts/`，和产品解析同一层级，不另设栏目，靠分类和标签关联，这样换主题时不用兼容特殊格式。知识文章先定位：对照 [writing/手册大纲.md](../../../writing/手册大纲.md)，定下它属于哪个主题（决定 `categories`）、英文 slug 和标签。

**完成标准**：路径、slug、分类、标签确定，并告诉了作者。

## 1. 列素材清单

按 `写作规范.md` 的“必须问作者的素材”，列出这篇文章需要作者提供什么。

- 需要素材：把清单发给作者，**停下来等回复**。不猜，不用训练数据里的印象代替。
- 不需要：告诉作者“这篇不需要额外素材”，然后继续。

复制 `writing/reviews/_template.md` 为 `writing/reviews/<slug>.md`，这一篇所有过程都记在里面。

**完成标准**：素材齐全，或已确认不需要。

## 2. 查资料

用 WebSearch / WebFetch 查一级来源，二级来源作补充（等级见 `写作规范.md`）。训练数据里的知识只能用来**找方向**，写进文章的每个事实都要有这次查到的出处。

每个用到的来源记进审阅记录的“资料”表：用途、来源、链接、访问日期。

**完成标准**：文章要用到的每个数字、规定、定义都有一条来源记录；查不到的已决定不写。

## 3. 写初稿

- 按七段骨架写，front matter 用下面的模板。
- 需要图示时，按 [writing/视觉规范.md](../../../writing/视觉规范.md) 画：说明性图示加载 `diagram-design`，数据图加载 `dataviz`，互动工具加载 `frontend-design`。先问一句：这张图比文字更快让读者懂吗？
- 链接站内已有的相关文章（`/posts/<slug>/`）；还没写的文章不放链接，用“讲某某的文章（还在写）”这样的说法，并在审阅记录里记下来。不要在正文里写“第几章”，站点没有章节结构。

```yaml
---
title: "标题写成读者心里的问题或结论"
description: "一句话摘要，显示在列表页"
date: YYYY-MM-DD
lastmod: YYYY-MM-DD
reviewed: YYYY-MM-DD   # 最后一次核实事实的日期
categories: ["保险入门"]   # 按 writing/手册大纲.md 的主题分类
tags: ["入门"]
ShowToc: true
---
```

**完成标准**：七段齐全；每个事实都能在“资料”表里找到出处；`hugo --quiet` 构建无报错。

## 4. 事实核查

派一个 `fact-checker` agent，给它文章路径（产品解析另给条款文本路径）。

把判定为有误、误导、无法核实的条目**全部**改掉，处理结果记入审阅记录。改动较大时再派一次核查。

**完成标准**：没有未处理的“必须改”。

## 5. 读者对抗审阅（只跑一轮）

**并行**派出三个 `reader-reviewer` agent，互相看不到对方的意见：

- 小王、老李，每篇都参加
- 第三位按主题从 `writing/读者人设.md` 挑选，挑选理由写进审阅记录

只跑这一轮，不开第二轮。汇总意见后逐条处理：

- **准确性优先**。读者要求删掉的内容如果删了会误导，就换一种更简单的讲法，不删。
- 读者产生了错误理解的，一定要改写法。
- 只靠改表达就能解决的（看不懂、有歧义、缺解释、跳步），直接改。
- 需要新资料、没有一级来源、超出本篇范围、或者要作者提供素材的，不在文章里硬补，统一记进 [writing/读者问题汇总.md](../../../writing/读者问题汇总.md) 这篇文章的小节，由作者判断要不要补。每位读者末尾“读完我还想问的问题”，文章没回答的，也记进去。
- 改动涉及事实的，按第 4 步重新核查改动部分。

**完成标准**：每条意见要么已改，要么已记进读者问题汇总；审阅记录里写明处理结果。

## 6. 去 AI 味

三层按顺序做，后一层不推翻前一层：

1. **AI味规则.md**：先运行 `python writing/scripts/check_ai_words.py <文章路径>`，禁用词全部改掉；再对照句式规则和“你补充的规则”，逐条检查全文。
2. **lieflat-less-ai-tone**：加载这个 skill，按它的白名单改写。
3. **humanizer-zh**：加载这个 skill，**只用“只标问题”模式**，列出命中项，不让它整篇重写。逐条判断：采纳的自己改，不采纳的写明原因。

三层都不能改变事实、数字、条款引用和文章结构。改完再运行一次禁用词脚本。

**完成标准**：禁用词脚本 0 命中；三层的处理结果都记入审阅记录。

## 7. 视觉审阅

确认本地有 hugo server 在跑（没有就在后台启动 `hugo server -D`），然后派一个 `visual-reviewer` agent，给它页面路径。

改掉所有“必须改”，再截一次图确认。

**完成标准**：检查表的每一项都是“通过”。

## 8. 交给作者预览

运行 `hugo --minify` 确认无报错，然后停下来，给作者：

- 本地预览地址
- 审阅记录路径，以及三五句话的摘要：核查了多少条、主要改了什么
- 读者问题汇总里这批新增了哪些，以及其他需要作者拍板的判断

**不要 commit，不要 push**，等作者确认。

**完成标准**：作者明确说可以发布。作者提出修改时，改完后回到对应步骤（改事实回第 4 步，改写法回第 5 步）。

## 9. 发布

作者确认后：

1. `reviewed` 和 `lastmod` 更新为今天
2. 只提交这篇文章相关的文件：文章、图片、H5、审阅记录；不用 `git add -A`
3. commit 信息：`feat(posts): 新增《标题》`
4. 作者要求推送时才 `git push origin master`，CI 自动部署；没说推送就只提交到本地

## 新文章替代旧文章

写到下面这些主题时，新文章替代旧文章。slug 不同的，在新文章 front matter 里加 `aliases` 指向旧地址，并删除旧文章，让旧链接跳转过来。

| 旧文章 | 被替代的主题 |
|---|---|
| `content/posts/health-insurance-guide.md`（`/posts/health-insurance-guide/`） | 险种类“百万医疗险” |

## 批量模式

作者说“写某个主题的一批”“写大纲里的第 X 部分”或给出一批主题时：

1. 列出这一批的文章清单（4–6 篇）、每篇的 slug 和顺序，以及整批的素材清单，一次性问作者。
2. 每篇**单独**走完第 2–7 步，每篇都有自己的审阅记录。
3. 整批做完后，一起进入第 8 步。作者逐篇确认后，按篇分别 commit。
