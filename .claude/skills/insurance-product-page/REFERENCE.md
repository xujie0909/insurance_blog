# Reference — 保险产品页生成规范

## blog-writing-style

### 读者画像

写每一句话之前，记住你在跟谁说话：

- **保险认知**：近乎为零。不知道"免赔额""等待期""现金价值"是什么。
- **医学认知**：近乎为零。"恶性肿瘤——重度""质子重离子""硼中子俘获"这些词对他们来说是乱码。
- **阅读场景**：手机刷到，地铁上看，睡前翻翻。注意力极短。
- **心理状态**：知道自己该买保险，但觉得条款像天书，怕被坑，怕买错。

你的任务：**用他能听懂的话，告诉他这份保险能在什么生活场景下帮到他。**

### 核心原则

1. **优势重点突出，劣势一笔带过。** 这是帮助用户理解产品价值的文章，不是学术论文。不保证续保、医院限普通部这类硬伤，用一两句话交代即可，不要反复敲打。
2. **公司背景不需要展开。** 除非公司特质直接影响产品设计（如财产险公司不能做保证续保），否则跳过。
3. **场景 > 定义。** 不要写"外购药械费用保险金是指被保险人在院外购买的……"，要写"医生开了处方，然后说'这药医院没有，你去外面买'——这个保险帮你出这笔钱。"
4. **用生活比喻解释复杂概念。** "免赔额就是你自己先出满一万，超出的它来报"、 "三层保护网：日常一层、重病一层、进阶一层"。
5. **短段落，碎节奏。** 有些段落就该一句话。连续五六段长段落读者就跑了。

### 语言规范

**医疗术语 → 大白话对照表：**

| 条款原文 | 改写后 |
|---------|--------|
| 恶性肿瘤——重度 | 癌症（比较严重的那种） |
| 恶性肿瘤——轻度 | 早期癌症 / 还没扩散的癌 |
| 脑卒中 | 脑中风 |
| 质子重离子治疗 | 精准打击肿瘤的高端放疗 |
| 硼中子俘获治疗 | 给癌细胞做标记然后定点炸掉 |
| 光免疫疗法 | 让癌细胞对光敏感然后照光杀死 |
| 外购药械 | 在院外药店买医生开的药和器械 |
| 特定药品 | 抗癌的靶向药、免疫药 |
| 免赔额 | 报销门槛（自己先出满XX块） |
| 等待期 | 买完保险到它能用的那段时间 |
| 犹豫期 | 买了后悔可以全额退的期限 |
| 保险金 | 保险公司赔给你的钱 |
| 给付比例 | 按多少比例报销 |

**禁用词清单：**

这些是 AI 写作的典型痕迹，**一个字都不要出现在文章里**：

- "此外"、"总而言之"、"值得注意的是"、"不可否认"
- "一方面……另一方面……"
- "这意味着什么？"（AI 自问自答的标志）
- "说实话"、"说真的"（AI 装亲切的套话）
- "我来举个例子"（直接举例，不用预告）
- "写到这里……"、"最后……"（不要评论自己的写作）
- "综上所述"、"整体而言"
- "建议根据自身需求选择"（正确的废话，删掉）

### 结构指南

**不要**用 "一、二、三、四" 的论文框架。读者不是来上课的。

**可以**用这样的自然过渡：
- "先说最常用的一块：……"
- "再聊一个很现实的问题：……"
- "第三块：万一得了大病……"
- "还有一个容易忽略的：……"

**开头**：直接切入，不用"随着人民生活水平提高……"、"在当今社会……"这种起手式。第一段就该让读者觉得"哎这说的是我"。

**结尾**：收在一个简单的总结或比喻上（比如"三层保护网"），不要煽情升华。

### 内容优先级

写作时按这个优先级分配篇幅：

1. **核心保障（住院 + 外购药械）** — 最大篇幅，这是读者最可能用到的
2. **大病保障（重疾0免赔 + 特药 + 先进疗法）** — 次大篇幅，这是产品的差异化优势
3. **康复 / 护工 / 异地转诊** — 中等篇幅，这些是加分项
4. **可选责任（门急诊）** — 小篇幅，说清楚加不加的判断标准即可
5. **免赔额计算** — 用一个数字例子讲清楚，不要列公式
6. **不保什么** — 列举最常见的几项，不要逐条翻译免责条款
7. **续保规则** — 两句话交代

## ai-anti-patterns

以下是本次迭代中踩过的坑，每次写文章前过一遍：

### 毛病一：八股文段落

```
❌ "外购药械是尊享e生2026版的核心卖点之一。在当前医疗环境下，医院药房备药不足的问题日益突出，
   很多患者面临医生开了处方却需要在院外购药的困境。尊享e生将外购药械费用纳入主条款，
   这体现了其对用户需求的深刻洞察。"
   → 每一段都是"观点→展开→升华"，像在写申论。

✅ "医生开了处方，说'这药我们医院没有，你去外面买'。
   没有保险——自己掏钱。这份保险——它帮你出。"
   → 用场景说话，不帮读者总结"意义"。
```

### 毛病二：假装有人设

```
❌ "我花了一个周末坐在电脑前把这份条款翻烂了"、"写这篇文章的时候我一直在想"
   → 读者一眼看出是演的。

✅ 不要在文章里强调自己多辛苦、多专业。专业度从对条款细节的
   熟悉程度自然漏出来，不是喊出来的。
```

### 毛病三：面面俱到

```
❌ 把100种重疾每种都点评一遍，把每一项释义都转述一遍。
   → 读起来像药品说明书。

✅ 只挑最容易出问题的几个讲透（甲癌、心梗、脑中风）。
   剩下的留给读者自己去翻条款。
   文章的深度不来自覆盖面，来自对关键细节的挖掘。
```

### 毛病四：过度平衡

```
❌ "这项责任有其优势，但也存在一定局限性，消费者应根据自身情况权衡。"
   → AI 的标准免责声明，怕得罪人。

✅ "硼中子国内目前基本用不到，现在算噱头。
   但如果五年后国内落地了，你手里正好有这份保险——那就赚了。"
   → 有判断、有态度，哪怕是主观判断也比模棱两可强。
```

### 毛病五：AI 高频词汇

以下词汇在本次对话中反复出现，已被标记为 AI 痕迹，**全部禁用**：

说实话、说真的、值得注意的是、不可否认、这意味着、我的态度是、
写到这里、综上所述、整体而言、根据自身需求选择、当然了、不过话说回来

**替代方案**：删掉这些词，句子直接连上去。90% 的情况下删掉它们不影响语义。

## blog-article

### Front Matter 模板

```yaml
---
title: "<产品名>深度解析：<核心卖点>"
date: YYYY-MM-DD
draft: false
categories: ["重疾险"]          # 或 医疗险 / 寿险 / 少儿保险
tags: ["<产品名>", "<公司名>", "重疾险", "保障解析"]
description: "<100字以内摘要，含核心数字>"
cover:
  image: ""
  alt: "<产品名>深度解析"
---
```

### 文章结构（建议顺序，可灵活调整）

以下结构适用于"测评/拆解"型文章。核心逻辑：**从读者最可能用到的场景开始，逐步深入到更小众但重要的保障。**

1. **一句话开篇**（50字以内）— 直接切入，不要背景铺垫。比如："买保险最烦条款看不懂，这篇文章不跟你拽术语。"
2. **核心保障：住院 + 外购药械**（最大篇幅）— 读者最可能触发理赔的场景
3. **大病保障：重疾0免赔 + 特药 + 先进疗法**（次大篇幅）— 产品的差异化优势
4. **加分项：康复 / 护工 / 异地转诊**（中等篇幅）— 让他觉得"考虑的还挺全"
5. **可选责任**（小篇幅）— 说清楚加不加
6. **免赔额怎么算**（一个例子讲清楚）— 不要列公式
7. **不保什么**（列举最常见几项）— 不要逐条翻译免责条款
8. **续保一句话交代**
9. **结尾**（简单总结，不煽情）

Mermaid 图表从原来的"必选项"降为"有就加、没有也不影响阅读"。不要为了塞图表而塞图表。

### Mermaid 使用规则

- 脑图用 `mindmap`，流程图用 `flowchart LR` 或 `flowchart TD`
- 节点文字不要有特殊符号（括号除外），避免解析错误
- Hugo `--minify` 会破坏缩进，**不要使用 `--minify` 构建含 Mermaid 的文章**（或确认站点已有 Mermaid 修复脚本）

## h5-design

H5 页面风格统一为**浅色系 + 卡片式布局**，干净清爽，适合在手机和桌面端阅读条款分析。

### CSS 变量（复用此配置，保持视觉统一）

不同产品可更换 `--primary` 色系（医疗险用绿、重疾险用蓝、少儿险用紫），其余变量保持一致。

```css
:root {
  --primary: #1a6e5c;              /* 主色，按产品类型调整 */
  --primary-light: #e8f5f1;        /* 主色浅底 */
  --accent: #e8873a;               /* 强调色（可选责任等） */
  --accent-light: #fff5ed;         /* 强调色浅底 */
  --danger: #c0392b;               /* 警示色（免责等） */
  --danger-light: #fdecea;         /* 警示色浅底 */
  --bg: #f7f8fa;                   /* 页面背景 */
  --card: #ffffff;                 /* 卡片背景 */
  --text: #2c3e50;                 /* 正文颜色 */
  --text-secondary: #5a6c7d;       /* 辅助文字 */
  --border: #e2e8f0;               /* 边框 */
  --shadow: 0 1px 3px rgba(0,0,0,.06), 0 1px 2px rgba(0,0,0,.04);
  --radius: 12px;                  /* 卡片圆角 */
  --radius-sm: 8px;                /* 小元素圆角 */
}
```

### 产品配色对照

| 产品类型 | --primary | Hero 渐变 | 适用 |
|---------|-----------|-----------|------|
| 医疗险 | `#1a6e5c` | `#0d4f41 → #1a6e5c → #1e8b73` | 尊享e生等 |
| 成人重疾险 | `#1a4a6e` | `#0d2e4f → #1a4a6e → #1e6b9b` | 达尔文12号等 |
| 少儿重疾险 | `#7b4a9e` | `#4a1a6e → #7b4a9e → #9b6ec0` | 达尔文宝贝计划等 |

### 必含模块

| 模块 | 实现方式 | 说明 |
|------|---------|------|
| Hero 头图 | 渐变背景 + 产品名 + 公司名 + 日期 | 用 `::before` 伪元素加 SVG 纹理 |
| 导航目录 TOC | `flex` + 圆角胶囊链接，hover 变主色 | 锚点跳转到各 section |
| 产品概览 | `params-grid`（CSS Grid，最小列宽200px） | 6个参数卡片：年龄/期间/等待期/犹豫期/保额/续保 |
| 保障责任卡片 | `coverage-grid`（CSS Grid，最小列宽300px） | 每张卡片：标签（必选/可选）+ 编号 + 标题 + 描述 + 列表。顶部3px色条区分必选/可选 |
| 理赔流程 | `flow-row`（flex，步骤+箭头） | 横向5步，手机端竖向 |
| 关键参数表 | `table` 完整表格 | 保险期间/等待期/犹豫期/免赔额/给付比例/医院范围等 |
| 责任免除 | `exclusion-section` 折叠面板 | 红色 header + 编号，内容用 grid 排列 |
| 要点总结 | 绿色优势列表 + 红色风险列表 + 警示框 | 双列 grid，responsive |
| Footer | 条款来源 + 免责声明 | 居中，小字 |

### 不使用的旧风格元素

以下为旧版深色主题的设计元素，**新页面不再使用**：
- ❌ 深色背景（`#060812`）+ 玻璃拟态卡片 + 渐变光晕球动画
- ❌ Bento Grid 布局、手风琴列表、数字滚动计数、IntersectionObserver 滚动淡入
- ❌ 底部固定 CTA 栏
- ❌ 多色渐变文字（`--blue-a/b`, `--gold-a/b` 等）

### H5 页面代码模板

直接以 `static/pages/zhongan-zunxiang-esheng-2026/index.html` 为基准模板，复制后替换：
1. `<title>` 和 Hero 中的产品名、公司名
2. `:root` 中的 `--primary` 和 `.hero` 渐变背景
3. 概览参数、保障责任卡片、免责条款、赔付场景的具体内容

## 内容质量检查清单

生成完成后逐项确认：

**博客文章：**
- [ ] 零 Mermaid 图表，全部使用 Markdown 表格
- [ ] 零 AI 禁用词（见 [blog-writing-style](#blog-writing-style) 禁用词清单）
- [ ] 所有医学术语已改写为白话（见术语对照表）
- [ ] 优势重点突出，劣势/免责一笔带过
- [ ] 有具体数字的赔付场景示例（如"50万保额举例"）
- [ ] 开头有 H5 跳转卡片（rawhtml shortcode）
- [ ] 段落短，节奏碎，无"一、二、三"论文框架

**H5 页面：**
- [ ] 浅色系（`--bg: #f7f8fa`），白色卡片，非深色背景
- [ ] 主色按产品类型正确（医疗绿/重疾蓝/少儿紫）
- [ ] 含 Hero + TOC + 概览 + 保障卡片 + 理赔流程 + 参数表 + 免责 + 总结
- [ ] 手机端 responsive（`@media max-width:768px`）
- [ ] Footer 含条款来源和免责声明
- [ ] 无深色主题残留（无 `.orb`、`.glass`、`backdrop-filter`、渐变光晕等）

**构建验证：**
- [ ] `hugo --minify` 构建无 ERROR
- [ ] Static files 计数 ≥ 产品数
